# Deployment

OreFlow has two public serving paths. GitHub Actions builds `frontend/dist` with `VITE_BASE_PATH=/CAOS_OreFlow/` and publishes the project site at `https://fsantibanezleal.github.io/CAOS_OreFlow/`. The build emits a matching `404.html` for direct GitHub Pages document routes, and React Router uses the project basename. The authoritative service is `https://oreflow.ml.fasl-work.com/` on the ML VPS, using the repository's FastAPI app behind nginx and TLS on port 8146. The VPS build uses the default root base path; `SpaStaticFiles` serves `index.html` with HTTP 200 for document routes while retaining real 404s for missing assets and API paths.

The VPS procedure is in `deploy/setup-vps.sh`, `deploy/oreflow.service`, `deploy/oreflow.nginx` and `deploy/oreflow.nginx.tls`. It clones the public repository, creates a runtime environment from `requirements-api.txt`, builds the SPA with Node 22, installs the systemd unit, requests a certificate and then installs the explicit OreFlow TLS virtual host. Deployment must check `/healthz`, `/api/cases`, `/api/benchmark`, the page title, direct `/methodology` and `/benchmark` navigation, and a representative `/api/simulate` request. Verify HTTPS with the public hostname, not localhost or generic nginx TLS.

The release boundary is deliberate: deployment copies or builds existing evidence and never trains, benchmarks or mutates the canonical artifact tree.
