# Workbench shell and focus route: requirements

Status: live

ADR-0058 requires the shared application shell. ADR-0070 applies because OreFlow has an interactive process workbench with a selected case and live controls; Focus mode opens that process instrument in a stage-sized route and restores the selected state on return.

| ID | Requirement | Verification gate |
| --- | --- | --- |
| WB-014 | THE product SHALL declare whether its primary route is a workbench or a surface in `product.json`; the design gate SHALL reject an invalid kind and shall not let gate arguments redirect the required Focus measurement. | `tests/adversarial/test_app_kind.py::test_the_template_example_is_a_workbench_with_focus_and_passes` |
| WB-015 | WHEN a product waives Focus mode, THE waiver SHALL be limited to a surface and SHALL give the same substantive reason in `product.json` and the SDD's ADR-0070 row. | `tests/adversarial/test_app_kind.py::test_a_reason_that_differs_from_the_sdd_row_fails` |
| WB-016 | WHEN Focus mode displays a calculated flowsheet, THE App SHALL let the user step or play through its applicable unit operations, pause, adjust the step interval, and inspect each operation's computed input/output stream quantities, grades and balance closure; THE App SHALL identify this as a steady-state inspection sequence rather than elapsed plant time. | `tests/adversarial/test_oreflow_requirements.py::test_adversarial_wb_016` |
| WB-017 | WHEN Introduction opens, THE page SHALL use the installed shared document surface and ExecutiveView, default to Executive, retain all five executive sections and linked sources, and make every authored field reachable by scrolling and keyboard in EN/ES, both themes, at 1280x800 and 390x844. | `frontend/src/test/introduction-claims.test.ts::adversarial: executive evidence cannot disappear from the shared reader`; installed shell gate ADR-0017.2 |
| WB-018 | WHEN either Introduction view enters Focus, THE page SHALL use shared SurfacePage Focus, retain its nested selected topic on return, and support direct `view`/`focus` navigation and Escape without replacing the executive renderer or adding shell CSS. | `frontend/src/test/introduction-claims.test.ts::adversarial: both introduction views retain Focus and onward navigation`; actual browser Focus and keyboard matrix |
| WB-019 | WHEN the technical Introduction is read, THE page SHALL preserve all six topic groups, the required problem/principles prose, mathematics equations and ten glossary items, one scope callout, four pipeline steps and existing figures/references; source links SHALL remain real destinations. | `frontend/src/test/introduction-claims.test.ts::adversarial: technical areas retain their content floors in both languages`; installed shell gate and screenshot inspection |
| WB-020 | WHEN the learned lane runs in development, THE server SHALL serve the copied ONNX runtime module unchanged for its runtime import, preserve ordinary handling of unrelated module paths, and use the same runtime bytes as the production build. | `frontend/src/test/ort-dev-assets.test.ts::adversarial: the development server serves the copied ONNX module unchanged` |
| WB-021 | WHILE artifact-backed document content is pending, THE visible pending surface SHALL declare the shared shell loading state, retain its accessible EN/ES status, and remain pending independently of other panels until its real data resolves; failures SHALL retain a visible localized alert without fabricated data. | `frontend/src/test/content-loading.test.ts::adversarial: pending document artifacts keep shared readiness busy in English and Spanish`; `frontend/src/test/content-loading.test.ts::adversarial: failed artifacts retain bilingual alerts and independent pending state` |
| WB-022 | THE guided process story SHALL declare its 3 to 6 direct routes in `product.json` `showcase.story_routes`; the runner SHALL walk the App, documentation and exactly those story routes, and the story check SHALL verify each rendered step, direct step links, pause on reader input and return to the App with state. | `tests/adversarial/test_adoption_defects_0_15_001.py::test_adversarial_a_missing_or_invalid_story_fails_the_sdd_guard`; `frontend/scripts/check_story_mode.mjs` |
